# T-12 휴강 등록·보강 조율

첨부 안내에 따라 임시 일정 홈은 구현하지 않았습니다. 독립 미리보기의 빈 배경 위에 바텀시트만 렌더링합니다.

## 동작

- 휴강하고 보강 날짜 받기: 휴강 등록 콜백 성공 후 후보 선택 단계로 이동
- 이미 휴강한 T-10 완료 화면의 보강 조율하기: 후보 단계로 바로 이동
- 후보 1은 기본 항목으로 삭제 버튼이 없고, 후보 2·3에만 삭제 버튼 표시
- 최대 3개, 추가·삭제 후 번호 및 CTA 개수 갱신
- 날짜 필드 터치 후 달력 선택, 시간 선택(30분 단위), 유효한 날짜·시간 검사 및 중복 후보 차단
- 날짜·시간이 빠지거나 수신 동의가 없으면 공유 비활성화
- 저장·공유 처리 중에는 입력·추가·삭제·취소·배경 닫기 차단
- 실패 시 후보와 입력 유지 및 재시도
- 시간만 바꾸기는 날짜를 유지하는 별도 시간 변경 콜백
- 달력/시간 선택을 취소하면 기존 후보 입력 유지

## API 연결 경계

`MakeupSheet`에 `MakeupLesson`과 `MakeupActions`를 전달합니다. API·카카오 SDK·실제 수신자 선택/전송은 미확정으로 연결하지 않았습니다. `previewActions.ts`만 지연·실패 예시를 생성합니다.

카카오 공유 창 열림과 실제 전송 완료는 구분합니다. 공유 결과는 opened/cancelled/unavailable로 처리하며 미리보기는 실제 메시지를 보냈다고 표시하지 않습니다. 실제 서버가 휴강 등록을 완료한 후 후보 선택을 취소해도 이미 등록된 휴강을 자동으로 취소하지 않습니다.

후보 날짜의 과거 허용 여부·수업 전 보강 가능 여부·시간 간격은 API/기획 확인이 필요합니다. 현재 날짜의 유효성과 중복만 검사하며 임의로 과거 날짜를 제한하지 않습니다.

## 개발 경로

- `/dev/makeup-coordination`: 최초 바텀시트
- `?scenario=loading`: 휴강 등록 처리 중 3초 대기
- `?scenario=error`: 첫 처리 실패 후 재시도 성공
- `?step=candidates`: 빈 후보 1개로 시작
- `?step=candidates&count=1`: 유효한 후보 1개
- `?step=candidates&count=2`: 후보 2개, 후보 2에만 삭제 버튼
- `?step=candidates&count=3`: 최대 3개
- `?step=candidates&count=1&scenario=error`: 첫 공유 실패 후 재시도
- `?step=candidates&count=1&scenario=share-cancelled`: 공유 취소 안내
- `?step=candidates&count=1&consent=no`: 수신 동의 없음
- `/dev/session-complete`의 보강 조율하기에서도 연결됨

개발 전용 진입점은 production에서 홈으로 이동합니다. 실제 일정 화면의 이벤트 연결은 담당 화면에서 콜백을 연결해야 합니다.

날짜 필드 안의 별도 달력 아이콘은 표시하지 않습니다. 날짜 필드 전체를 누르면 달력이 열리고, 시간 필드는 시간 선택이 열립니다. 일정 홈은 담당 화면에서 시트를 호출하는 방식으로 연결합니다.
